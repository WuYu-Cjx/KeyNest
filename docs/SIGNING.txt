================================================================
键巢（KeyNest）数字签名与杀软误报说明
================================================================

一、为什么需要数字签名
----------------------------------------------------------------
键巢使用低级键盘钩子（WH_KEYBOARD_LL）实现快捷键提示。该 API 被大量
输入法、截图工具与辅助软件使用，但部分安全软件会对“未签名的键盘钩子程序”
给出启发式告警。代码签名可以显著降低误报率，并让用户在 SmartScreen 中看到
可验证的发布者名称。

二、签名建议
----------------------------------------------------------------
1) 证书类型
   · 推荐：OV / EV 代码签名证书（由受信任 CA 签发）。
   · EV 证书可更快建立 SmartScreen 信誉。
2) 签名对象
   · dist\KeyNest-Setup.exe（安装器，最终交付物）
   · KeyNest.App.exe（主程序）
   · KeyNest.Uninstaller.exe（卸载程序）
3) 时间戳
   · 必须使用 RFC 3161 时间戳服务器，确保证书过期后签名仍然有效。
4) 签名顺序
   · 先对主程序与卸载器签名 → 再打包 payload.zip → 最后对安装器签名。
   · 任何在签名后修改安装包内容的行为都会使签名失效。

三、示例命令（需自行替换证书与时间戳地址）
----------------------------------------------------------------
signtool sign /fd SHA256 /tr http://timestamp.example.com /td SHA256 ^
  /f "path\to\codesign.pfx" /p "<password>" ^
  "dist\KeyNest-Setup.exe"

验证：
signtool verify /pa /v "dist\KeyNest-Setup.exe"

说明：以上仅为通用流程示例，不包含任何第三方脚本或工具代码；
     实际证书申请与签名请由具备资质的发布主体完成。

四、常见杀软误报与应对
----------------------------------------------------------------
现象：安装或首次运行时提示“未知发布者”“可能不需要的程序”或行为拦截。
原因：
  1) 安装包未签名或签名证书信誉不足；
  2) 程序安装键盘钩子，被启发式规则标记；
  3) 程序写入 HKCU Run 项（开机自启，默认关闭）；
  4) 单文件自解压目录被误判为释放行为。

应对：
  1) 完成代码签名，并在签名后重新打包，避免二次修改；
  2) 在隐私说明与许可页明确告知钩子用途（仅读取修饰键状态，不记录内容）；
  3) 开机自启默认关闭，安装选项中明确说明；
  4) 向主流安全厂商提交误报申诉，附上安装包哈希、签名信息与功能说明；
  5) 保留 THIRD-PARTY-NOTICES.txt 与 PRIVACY.txt 以便审查。

五、用户沟通建议
----------------------------------------------------------------
· 在下载页说明：键巢不联网、不上传数据、不记录按键历史。
· 说明默认不拦截系统快捷键；接管单按 Win 为可选项且默认关闭。
· 提供卸载入口：Windows 设置 → 应用 → 已安装的应用 → 键巢（KeyNest）。
